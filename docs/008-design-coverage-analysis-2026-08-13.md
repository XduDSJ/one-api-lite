1. **管理后台核心功能 100% 覆盖**：渠道/令牌/用户/日志/设置/仪表盘/分组预留

4. **渠道运维子功能基本完整**：详情页含密钥管理+模型列表，列表页含测试/余额
5. **后端 API 全覆盖**：所有管理后台 API 都有对应前端设计

## 附录 2：Nav 项组件化（2026-08-14 执行）

上述"Nav 项建议组件化"已完成。彻底解决"复制后配色漂移"问题。

### 组件源
| 组件 | ID | 说明 | 位置 |
|---|---|---|---|
| Comp-NavItem-Active | 18:1 | 选中态 Nav 项：Nav背景白0.06+Icon背景白0.08+字母白+Label白 | 仪表盘页 Sidebar(3:446) |
| Comp-NavItem-Default | 18:2 | 未选中态 Nav 项：Nav透明+Icon背景白0.05+字母灰#A1A1AA+Label灰 | 仪表盘页 Sidebar(3:446) |

### 实例分布（47 实例 + 2 组件源 = 49 Nav 项）
- 7 个 Sidebar × 7 个 Nav 项 = 49 个 Nav 项全部组件化
- 选中态实例 6 个（渠道页/3:1008/令牌页/用户页/日志页/设置页各 1 个）→ ref 18:1
- 未选中态实例 41 个 → ref 18:2
- 每个实例用 descendants 覆盖字母(content)和标签(content)，样式从组件源继承

### 使用方式
- **改 Nav 项样式**（背景/圆角/配色/字号）：改组件源 18:1 或 18:2 → 49 处同步
- **改 Nav 项内容**（字母/标签文字）：U("实例ID;子节点ID", {content: "新文字"})
- **切换选中/未选中状态**：U("实例ID", {mainComponent: "18:1"}) 或 "18:2"

### 技术发现
- `I()` 插入 ref 时支持 `descendants` 属性覆盖子节点内容，比"先 I 再 U"更高效
- 格式：`{type: "ref", ref: "组件源ID", descendants: {"子节点ID": {content: "新内容"}}}`
- 设 `reusable:true` 后子节点 ID 保留不变，descendants 用原始子节点 ID 即可

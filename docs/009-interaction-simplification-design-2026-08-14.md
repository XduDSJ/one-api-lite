# 009 - 交互简化设计方案

> **日期**：2026-08-14  
> **范围**：one-api 管理后台全局交互简化  
> **目标**：减少人工点击按钮数量，通过自动执行、默认值预设、批量处理、自动跳转替代手动操作

---

## 一、设计原则

### 核心理念

> 测试是用户主动触发的操作，不应进入页面就自动执行。

| 分类 | 原则 | 说明 |
|------|------|------|
| ✅ 合理自动化 | 自动预设参数 | 选择渠道类型后预设名称/分组/优先级默认值 |
| ✅ 合理自动化 | 自动获取模型列表 | 进入模型选择步骤自动从上游拉取，无需手动点击"从上游获取" |
| ✅ 合理自动化 | 自动解析Key | 粘贴Key后本地去空行/去重/计数，不调接口验证 |
| ✅ 合理自动化 | 自动跳转页面 | 完成渠道创建后自动跳转详情页，无需手动导航 |
| ✅ 合理自动化 | 自动刷新余额 | 列表页余额每5分钟自动刷新 |
| ✅ 合理自动化 | 自动同步模型 | 编辑弹窗开启"自动同步"后保存即同步 |
| ✅ 合理自动化 | 自动清理日志/禁用渠道 | 设置页配置周期后自动执行 |
| ✅ 合理自动化 | 输入即搜索 | 搜索框无需点击搜索按钮，输入即触发 |
| ❌ 不合理自动化 | 进入即测试 | 会把不必要的测试请求强加给上游，浪费额度 |
| ❌ 不合理自动化 | 自动验证Key连通性 | 同上，浪费上游API额度 |
| ❌ 不合理自动化 | 自动修改用户权限 | 安全风险，应由管理员主动操作 |
| ❌ 不合理自动化 | 自动删除数据 | 不可逆操作，必须有用户确认 |

### 配色规则

| 颜色 | 色值 | 含义 |
|------|------|------|
| 青色 | `#2DD4BF` | 自动化标识（自动执行的操作） |
| 琥珀色 | `#B86F05` | 手动主操作（需要用户点击的按钮） |
| 红色 | `#EF4444` | 危险/禁止操作 |
| 背景 | `#0D0D12` | 暗黑"演唱会"主题背景 |

## 二、各页面改造详情

### 1. 渠道添加向导 (3:2660) — 智能自动化流程

**新增节点**：AutoFlowCard (12:311)，青色边框卡片，展示5条自动化流程

| 序号 | 自动化项 | 原操作 | 改造后 |
|------|----------|--------|--------|
| ① | 类型选择→预设推荐参数 | 手动填写名称/分组/优先级 | 自动根据渠道类型预设默认值 |
| ② | Key粘贴→自动解析计数 | 手动逐行检查 | 本地去空行/去重/计数，不调接口 |
| ③ | 进入Step3→自动获取模型 | 手动点击"从上游获取"按钮 | 进入步骤即自动拉取 |
| ④ | 新增模型→默认全选 | 手动逐个勾选 | 默认全选，只需取消不需要的 |
| ⑤ | 完成创建→自动跳转详情页 | 手动导航到详情页查看 | 自动跳转 |

**快速模式提示**：粘贴Key后点击"下一步"自动跳过模型获取步骤，一键完成创建

**Step2 文字调整**：

- Footer 改为"粘贴Key后点击下一步，自动获取上游模型"

**Step3 文字调整**：
- CountText 改为"已自动获取8个模型·新增2个已全选·可取消不需要的"
- Footer 改为"模型已自动获取并全选新增，完成创建自动跳转详情页"

**修正记录**：
- 第②条从"自动验证有效性（实时调/v1/models测试连通性）"改为"自动解析计数（去空行/去重，不调接口验证）"
- 第①条从"Base URL自动填充"改为"自动预设推荐参数"（代码中无Base URL自动填充功能，base_url是用户手动输入字段）

### 5. 系统设置页 (3:2082) — 自动化运维卡片

**新增节点**：
- AutoOpsCard (12:360)：自动化运维配置卡片
- AutoOpsHint (12:389)：自动化运维提示行

**改造内容**：
- SettingsContainer (3:2122) 新增AutoOpsCard
- 4项自动化配置：

| 配置项 | 默认值 | 可选值 | 说明 |
|--------|--------|--------|------|
| 自动同步模型 | 每天 | 关闭/每小时/每天/每周 | 定时同步渠道模型列表 |
| 自动清理日志 | 180天 | 关闭/30天/90天/180天/365天 | 超过指定天数的日志自动清理 |
| 自动清理禁用渠道 | **关闭** | 关闭/7天/30天/90天 | 禁用超过指定天数的渠道自动清理 |
| 自动刷新余额 | 5分钟 | 关闭/1分钟/5分钟/30分钟/1小时 | 按指定间隔自动刷新渠道余额 |

> **"关闭"选项**：每项下拉菜单均含"关闭"选项，选中后该项自动化不执行。设计稿中"自动清理禁用渠道"默认展示为"关闭"状态（灰色文字），因为自动删除渠道风险较高，应由用户主动开启。

**修正记录**：
- 原设计包含"自动测试间隔"项，用户反馈不需要
- 修正后：删除自动测试间隔，保留4项合理自动化
- 提示文字去掉"测试渠道"，改为"同步模型/清理日志/刷新余额"
- 子元素宽度统一改为fill_container修复超出父容器问题
- Body和页面clipsContent改为false，解决SettingsContainer高度溢出被裁切问题
- **补充"关闭"选项**：每项下拉菜单增加"关闭"选项，选关闭=该项不自动执行；"自动清理禁用渠道"默认改为关闭状态（风险较高，用户主动开启）

## 五、代码核实记录

### Base URL 自动填充调查

用户质疑"Base URL自动填充"说法后，核实前端代码：

**`channel.constants.js`**：
- `CHANNEL_OPTIONS` 数组只有 `key/text/value/color/description/tip` 字段
- 没有 `base_url` 字段
- 仅 OpenAI兼容(key:50) 的 description 提到"支持设置Base URL"

**`EditChannel.js`**：
- `base_url: ''` 初始化为空字符串
- `handleInputChange` 只做 `setInputs((inputs) => ({ ...inputs, [name]: value }))`
- 无任何根据渠道类型自动填充 base_url 的逻辑

**结论**：前端代码中不存在 Base URL 自动填充功能。AutoFlowCard 第①条已修正为"自动预设推荐参数（名称/分组/优先级默认值，减少手动填写）"。

## 5. 关键技术决策

### 决策 A：业务组件是改造还是重写
**改造**（保留 default 业务组件的导出函数和状态管理，只重写 JSX 渲染部分）
- 优势：API 数据流不变、useState/useEffect 逻辑不变、改动可控
- 劣势：受限于原组件的 props 接口
- **采用**：所有批次都用"改造"模式

### 决策 B：图表组件
设计稿用 `recharts`（已在依赖中），批次 1 重构 Dashboard 时统一为：
- 折线图：金色 + 渐变填充
- 柱状图：金/青双色
- 环形图：橙金/青/红多色

### 决策 C：响应式断点
设计稿基于 1920×1080，aurora-theme.css 已有 5 个断点：
- ≤768 移动端（边栏抽屉）
- ≤1366 紧凑
- 1367-1919 标准
- ≥1920 宽屏
- ≥2560 超宽

**表格在 ≤768 转卡片视图**（批次 1 渠道管理页需实现）

### 决策 D：构建与部署
- 每批完成后 build 验证 + 截图对比（用本地 serve 静态产物，对比设计稿截图）
- 每周一批次 commit + push + 触发 Docker CI（用户手动 workflow_dispatch）
